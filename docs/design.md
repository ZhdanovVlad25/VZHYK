## Концепція бренду

Назва "Вжик" — звуконаслідування швидкого руху (свист/змах), і водночас ім'я
реального мультяшного персонажа (маленька бірюзово-зелена комаха з жовтою
мордочкою й червоною футболкою — класичний радянський/український мультик).
Дизайн-напрям навмисно відштовхується від кольорів цього персонажа, а не від
абстрактної "корпоративної" палітри — маркетплейс для людей, а не B2B-каталог:
енергійний, теплий, без зайвої строгості.

## Палітра (`apps/web/tailwind.config.js`)

| Токен | Стопи | Джерело | Семантика/використання |
|---|---|---|---|
| `brand` (бірюза) | 50, 100, 200, 500, 600, 700, 900 | тіло персонажа | Основний бренд-колір: лого, посилання, primary-кнопки, focus ring, активні вкладки, чат-бульбашки "мої повідомлення", фон карток оголошень (`bg-brand-50`/`bg-brand-100`) |
| `accent` (червоний) | 50, 100, 500, 600, 700 | футболка персонажа | Ціна оголошення, головна CTA "+ Додати оголошення", категорії (кожна 2-а) |
| `highlight` (жовтий) | 100, 400, 500, 900 | мордочка персонажа | Лого-бейдж "В", категорії (кожна 3-я) |
| `page` (тепле кремове, `#FBF6EE`, без стопів) | — | тепла підложка з референсного зображення персонажа | Фон `<body>` (`layout.tsx`) — навмисно не стерильний білий; хедер/картки лишаються білими/tint зверху й контрастують з підложкою |

Точні hex — дивись `apps/web/tailwind.config.js` (`theme.extend.colors`).

**Статусні кольори НЕ чіпати**: `Badge`/`Alert` (`apps/web/src/components/ui/`)
використовують стандартну Tailwind-семантику (green=success, amber=warning,
red=danger, blue=info) для станів оголошень/модерації — це UX-конвенція, не
брендинг, змішувати з `accent` (теж червоний, але означає "ціна/CTA", не
"помилка") небезпечно.

**Ротація кольорів для списків** (категорії на головній, `apps/web/src/app/page.tsx`
`CATEGORY_TINTS`) — масив `['bg-brand-100 text-brand-700', 'bg-accent-100
text-accent-700', 'bg-highlight-100 text-highlight-900']`, `index % 3`. Той
самий патерн можна перевикористати для інших списків категорій/тегів, якщо
знадобиться (наприклад `/search` фільтри).

## Типографіка ✅ вирішено

Пара шрифтів через `next/font/google` (`apps/web/src/app/layout.tsx`), обидва
`subsets: ['latin', 'cyrillic']`:

- **Unbounded** (ваги 500/800, `--font-unbounded` → `tailwind.config.js`
  `fontFamily.display`, клас `font-display`) — заголовки й лого. `h1`/`h2`/`h3`
  отримують його **автоматично** через `apps/web/src/app/globals.css`
  (`@layer` за межами tailwind, глобальне правило `h1,h2,h3 { font-family:
  var(--font-unbounded) }`) — не треба руками ставити `font-display` на
  кожному заголовку. Лого-текст у `Header.tsx` — окремо, бо це не `h1-h3`
  (явний клас `font-display`).
- **Rubik** (ваги 400/500/700/800, `--font-rubik` → `fontFamily.sans`,
  дефолтний для всього іншого) — body/UI-текст.

Відкинуті варіанти: Manrope (перший вибір, фідбек "сиро" — надто нейтральний),
Baloo 2 (занадто "дитячий" для суцільного тексту, лишився кандидатом лише для
заголовків, програв Unbounded).

## Форма/spacing

- Радіус: `rounded-xl` (12px) для кнопок/інпутів/дропдаунів/алертів,
  `rounded-2xl` (16px) для карток/модалок/картки оголошення. Раніше було
  `rounded-md`/`rounded-lg` (8px) — свідомо збільшено для "м'якішого" відчуття.
  `Badge` лишається `rounded-full` (пігулка, без змін).
- Бордери: тонкі (`border`, 1px), без товстих рамок.
- Хедер: пошуковий інпут і кнопка "Знайти" мають однакову явну висоту `h-8`
  + `items-center` на формі — без цього input (контентна висота ~38px) і
  Button `size="sm"` (`h-8`=32px) розʼїжджались по вертикалі, і "Знайти" не
  збігалося з "Увійти" в navbar.

## Ключові компоненти-приклади

- `apps/web/src/components/ui/Button.tsx` — variant `accent` (новий, для
  головної CTA), `primary` (бренд-бірюза), `secondary`/`ghost`/`danger` — без
  змін семантики.
- `apps/web/src/components/layout/Header.tsx` — лого = `<Logo className="h-7 w-7" />`
  (див. розділ "Лого" нижче) + `font-display` текст "Вжик" (mixed case, не
  капслок) кольору `text-brand-700`; CTA "+ Додати оголошення" — `variant="accent"`.
- `apps/web/src/components/layout/Logo.tsx` — SVG-компонент лого, кольори
  захардкоджені hex (не Tailwind-класи) — це пряме зображення персонажа,
  не UI-елемент, тому не повинно інвертуватись/змінюватись темою.
- `apps/web/src/components/listings/ListingCard.tsx` — ціна
  `text-accent-600 font-extrabold`, фон картки `bg-brand-50`/`bg-brand-100`
  (photo placeholder).
- `apps/web/src/app/page.tsx` — категорії з ротацією tint-кольорів (`CATEGORY_TINTS`).
- `apps/web/src/app/login/page.tsx` — resend-таймер (`RESEND_COOLDOWN_SECONDS = 60`)
  на кроці підтвердження коду: кнопка "Надіслати ще раз" вимкнена й показує
  зворотний відлік. Доданий після реального інциденту в цій сесії — без
  таймера легко наспамити кілька запитів коду поспіль (кожен новий інвалідовує
  попередній) і/або впертися в бекенд rate limit (3 запити/15хв на номер,
  docs/security.md §6), а користувач лишається зі "старим" кодом на руках,
  який більше не працює.
- `apps/web/src/components/layout/Header.tsx` `navLinkClass()` — active-стан
  навігації: `usePathname()` + `startsWith(href)`, поточний розділ отримує
  `bg-brand-100 text-brand-700`, решта — звичайний hover. Перевикористати
  цей патерн для будь-яких інших навігаційних списків, де потрібен active-стан.
- Кастомна кнопка вибору файлу (`apps/web/src/app/listings/[id]/edit/page.tsx`) —
  нативний `<input type="file">` показує текст кнопки мовою браузера
  (не контролюється CSS/HTML), тому реальний `<input>` ховається (`sr-only`,
  не `hidden`/`display:none` — лишається доступним для screen reader/keyboard),
  а клік делегується стилізованій `<Button>` через `fileInputRef.current?.click()`.

## Лого ✅ вирішено

Довгий перебір варіантів (абстрактні концепти — крапка-вусик, вихор,
шеврони-швидкість, шарувата "В", силует-щит з вусиками, значок з двома
колами — усі відхилені: "нічого з цього не подабається" /
"щось типу такого" з ескізами) → фінал: **пряме стилізоване обличчя
персонажа**, геометрично спрощене під квадратну іконку:

- Квадрат із заокругленими кутами (`rx=40` на `200×200`), фон `#238A80`
  (≈ `brand-600`, тіло персонажа).
- Два жовті квадратні ока (`70×70`, `rx=16`, `#F0C94A` = `highlight-400`) з
  великими чорними зіницями (`r=14`), зміщеними вниз-всередину (не по
  центру ока) — прямий центрований погляд читався як "здивований", зсув
  дає теплий/добріший вираз. Маленький білий відблиск-іскра в кожній
  зіниці.
- Чорний ніс-овал (`rx=16 ry=10`, `#1A1A1A`, не чистий `#000`) з білим
  відблиском — навмисно маленький, перша ітерація з великим круглим носом
  виглядала недоречно домінуючою.
- Червоний "светр" на всю ширину знизу, впритул до заокруглених кутів
  (через `clipPath` на форму квадрата, інакше кути светра стирчали б за
  межі заокруглення): тонка світліша смужка-комір (`#E13B32` = `accent-500`)
  + товстіший темний бордовий блок під нею (`#9B241D` = `accent-700`).
  Важливо: ЦЕ НЕ РОТ — перша версія (закруглена плашка по центру) читалась
  як усмішка, користувач явно перепитав "щоб виглядало як светр а не рот";
  двотоновість і повна ширина до країв — те, що відрізняє "одяг" від "рота"
  у цій композиції.

Реалізовано: `apps/web/src/components/layout/Logo.tsx` (React-компонент,
`viewBox="0 0 200 200"`, приймає `className` для розміру — у хедері
`h-7 w-7`) + `apps/web/src/app/icon.svg` (той самий SVG як статичний файл,
Next.js App Router підхоплює `app/icon.svg` як favicon автоматично, без
додаткової конфігурації).

**Якщо колись знадобиться повернутись до дизайну лого** — весь перебір
(включно з відхиленими абстрактними концептами) лишився в історії чату
цієї сесії, не тут; цей файл фіксує тільки фінальний результат і причини
ключових рішень (зсув зіниць, розмір носа, двотоновий светр).

## Відомі прогалини / наступні кроки

Усі пункти фідбеку з попереднього раунду (мало кольору, категорії без кольору,
білий фон карток, шрифт "сиро", фон сторінки білий, "Знайти"/"Увійти" не на
одному рівні, немає resend-таймера) — **відпрацьовано**. Що лишається на
розгляд для наступної сесії:

1. Решта сторінок (admin-панелі, форми, чат) досі майже повністю
   нейтрально-сірі/білі — новий колір поки що торкнувся лише публічної
   discovery-поверхні (головна, картка оголошення, хедер). Чи варто нести
   колір далі в адмінку — окреме рішення (адмінка традиційно
   стриманіша/функціональніша, не обов'язково повторювати playful-тон).
2. `highlight` (жовтий) все ще використовується лише в одній точці
   (лого-бейдж) + категорії — є простір для дрібних акцентів/notification dots.
3. Ротація кольорів категорій (`CATEGORY_TINTS`) — детермінована за індексом,
   не за типом категорії; якщо з'являться нові категорії, порядок кольорів
   може виглядати довільним. Не проблема зараз (12 категорій, глядач не
   рахує), але якщо колись знадобиться "заморозити" колір за категорією —
   треба буде мапу `categoryId → tint`, не `index % 3`.

## Історія рішень цієї сесії

1. Запропоновано 3 варіанти кольорового напряму (теплий корал+бірюза;
   "мультяшний" жовтий/червоний/синьо-зелений; фінальний — точні кольори
   персонажа з наданого зображення) — користувач підтвердив третій варіант.
2. Впроваджено базову систему: `tailwind.config.js` (brand/accent/highlight),
   Manrope (тимчасово), round radius bump, price→accent, лого-бейдж,
   CTA→accent variant, bulk border-radius sweep по ~15 файлах.
3. Фідбек після першого раунду: мало кольору, Manrope "сиро", категорії без
   кольору, білий фон карток, "Знайти"/"Увійти" не на одному рівні.
4. Показано 3 варіанти шрифтової пари (Baloo 2+Rubik, Unbounded+Rubik,
   лишити Manrope) — обрано Unbounded+Rubik.
5. Другий раунд впровадження: заміна Manrope → Unbounded (заголовки)
   + Rubik (body), ротація tint-кольорів на категоріях головної, tint-фон
   карток оголошень (`bg-brand-50`), фікс вертикального вирівнювання
   хедер-форми (`items-center` + явна `h-8` на інпуті).
