# ВЖИК — Product Requirements Document (PRD)

Статус: Phase 1 — Foundation
Версія: 0.2 (Phase 1 Authorization)

## 1. Продукт

«Вжик» — україномовна платформа оголошень (marketplace) з можливістю продажу, купівлі, обміну, безкоштовної передачі товарів, пошуку послуг, роботи та житла. MVP працює без онлайн-оплати, доставки та безпечної угоди — угода домовляється напряму між користувачами через внутрішній чат.

Референс для аналізу — OLX Україна (структура, категорії, сценарії), без копіювання бренду, UI, текстів чи графіки.

Перевірено фактичну структуру olx.ua (серпень 2026): верхньорівневі розділи сайту — Дитячий світ, Нерухомість, Авто, Запчастини, Робота, Тварини, Дім і сад, Електроніка, Бізнес та послуги, Житло подобово, Оренда та прокат, Мода і стиль, Хобі/відпочинок/спорт, Віддам безкоштовно, Обмін, «До речі, відомі речі» (вживані брендові речі). Це підтверджує категорійну структуру, закладену в вихідному документі, з одним зауваженням — див. `decisions.md` DEC-01 щодо «Житло подобово» як окремого top-level розділу.

## 2. Ролі користувачів

| Роль | Опис |
|---|---|
| Guest | Неавторизований відвідувач: перегляд, пошук, перегляд оголошень. Не може писати в чат, додавати в обране, публікувати. |
| User (Buyer/Seller) | Базова роль після реєстрації. Може публікувати оголошення, спілкуватись у чаті, додавати в обране, зберігати пошуки, скаржитись. |
| Moderator | Співробітник платформи. Обробляє чергу модерації фото/оголошень, скарги, блокування. |
| Admin | Повний доступ до Admin Panel: категорії, атрибути, користувачі, оголошення, статистика, audit log. |
| System / Service account | Технічна роль для фонових задач (індексація пошуку, нотифікації, антифрод-скоринг). |

Майбутні ролі (Phase 2+): Business Account, Support Agent (обмежений Moderator), Content Manager (керує тільки категоріями/атрибутами).

## 3. Основні user journeys (MVP)

1. **Реєстрація/вхід** — Guest → введення номера телефону → SMS OTP → підтвердження → створення профілю. Альтернатива: Google OAuth.
2. **Створення оголошення** — User → «Додати оголошення» → тип оголошення → категорія/підкатегорія → форма з динамічними атрибутами → фото → локація → чернетка/публікація → модерація → активне оголошення.
3. **Пошук і фільтрація** — Guest/User → пошук за текстом/категорією → фільтри (ціна, локація, атрибути, стан) → сортування → список результатів → перехід на картку оголошення.
4. **Перегляд оголошення** — картка оголошення → перегляд продавця → «Додати в обране» / «Написати продавцю» / «Поскаржитися».
5. **Чат і домовленість** — User A відкриває чат з User B з картки оголошення → обмін повідомленнями/фото → домовленість поза платформою (оскільки оплата/доставка не в MVP).
6. **Обране та збережені пошуки** — додавання оголошень в обране, збереження фільтрів пошуку, сповіщення про зміну ціни/недоступність.
7. **Скарга** — User → «Поскаржитися» на оголошення/чат/користувача → причина + опис + докази → чергу модерації.
8. **Модерація** — Moderator → черга (авто-флаги + ручні скарги) → перегляд → рішення (APPROVED/REJECTED/NEEDS_REVIEW) → повідомлення користувачу.
9. **Адміністрування** — Admin → dashboard, users, listings, categories, attributes, reports, moderation, audit log.

## 4. Функціональні вимоги (скорочено)

Повний перелік — розділи 6–41 вихідного документа. Ключове угруповання:

- **Auth & Identity**: Phone OTP, Google OAuth, сесії, refresh token, account recovery.
- **Profiles**: базові поля, «Мої оголошення» (активні/продані/архів/чернетки).
- **Categories & Attributes**: ієрархія Category → Subcategory → Sub-subcategory, керована з Admin Panel; динамічна модель атрибутів per category.
- **Listings**: CRUD, типи (Продам/Куплю/Обміняю/Віддам безкоштовно/Послуга/Оренда), state machine статусів.
- **Media**: завантаження фото, порядок, головне фото, стиснення, thumbnails, валідація.
- **Moderation**: пайплайн фото та оголошень, ручна черга, скарги.
- **Search**: повнотекстовий пошук + фільтри + сортування, абстракція над search engine.
- **Location**: область/місто/район/координати/радіус, без точної домашньої адреси.
- **Favorites & Saved Searches**: обране, price history, збережені фільтри, майбутні сповіщення про збіг.
- **Chat**: realtime 1:1 чат, фото, unread/read, typing/online, блокування, скарги.
- **Notifications**: абстракція над in-app/email/push.
- **Reports**: типізовані причини скарг, стан обробки.
- **Admin Panel**: dashboard, users, listings, categories, attributes, reports, moderation, audit log.
- **Security**: RBAC, rate limiting, upload validation, OTP security, audit logging.
- **Analytics**: базові продуктові події (без зайвих персональних даних).
- **Anti-Fraud**: RiskScore/RiskSignal, без автоматичного блокування за одним слабким сигналом.

## 5. Нефункціональні вимоги

- **Мова**: українська (MVP), архітектура готова до i18n.
- **Валюта**: UAH (основна), USD, EUR — зберігання ціни у мінімальних одиницях + курс на момент публікації.
- **Responsive**: mobile-first, Desktop/Tablet/Mobile; без нативних застосунків у MVP.
- **SEO**: SSR/SSG, canonical URLs, Open Graph, structured data (schema.org/Product, /JobPosting, /RealEstateListing), sitemap, SEO-friendly URLs (`/uk/{category}/{subcategory}/{slug}-{id}`).
- **Продуктивність**: lazy loading, pagination, caching (Redis), індекси БД, запобігання N+1.
- **Безпека**: див. `security.md`.
- **Масштабованість**: Modular Monolith з чіткими межами модулів, готовність до виділення в сервіси за потреби (насамперед Search, Chat, Media).
- **Спостережуваність**: структуровані логи, audit trail адмін-дій, базові метрики (Phase 8).

## 6. Що НЕ входить у MVP

Онлайн-оплата, доставка (Nova Poshta), escrow/безпечна угода, комісія, платні оголошення/TOP/VIP/підписки, бізнес-акаунти, рекламна біржа, нативні мобільні застосунки. Усе перелічене — архітектурно підготовлене через abstraction-шари (`PaymentProvider`, `ShippingProvider`), але без бізнес-логіки в MVP.

## 7. Результати gap-аналізу (стисло) — вирішено у Phase 1 Authorization

Повний перелік — `decisions.md`. Усі пункти нижче закриті продуктовими рішеннями (детально — відповідний DEC у `decisions.md`):

1. **Модерація «Робота»/«Нерухомість»** (DEC-02): окрема глибока category-specific модерація в MVP не реалізується, використовується загальна система модерації. Спеціалізовані правила — Phase 2.
2. **Ліміт оголошень** (DEC-05): максимум **5 активних оголошень** одночасно на звичайного користувача (не ліміт на добу), configurable через Admin Panel; майбутня диференціація для verified/business/платних тарифів.
3. Монетизація виключена з MVP — свідоме рішення, зафіксовано (DEC-07), архітектура готова через `PaymentProvider`.
4. «Житло подобово» — окрема top-level категорія MVP (DEC-01).
5. **Retention персональних даних** (DEC-04): 6 місяців зберігання PII після видалення акаунта, потім автоматизований cleanup/anonymization job.
6. **AI content-moderation для тексту** (DEC-08): не використовується в MVP, rule-based + manual + reports; архітектурно розширюване.
7. **Accessibility** (DEC-09): базова accessibility в MVP (семантика, labels, alt, keyboard nav, focus states, contrast, зрозумілі помилки, доступні modals, screen reader basics); повний WCAG 2.1 AA audit — наступний етап.
